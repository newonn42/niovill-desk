# 고시원 관리 프로그램 (niovill-desk)

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/newonn42/niovill-desk)

니오빌 홈페이지와 **별개의** 관리 전용 사이트입니다. 검색에 노출되지 않고(noindex, robots 차단), 첫 화면부터 로그인해야 합니다. 비용 0원 (Cloudflare 무료).

## 진행 단계
| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 데이터 구조 (호실·입실자·납부 예정·입금·배정·월세 변경·보증금·변경 이력) | ✅ |
| 2 | 로그인 · 최고/일반 관리자 · 초대 링크 · 끄기 · 비밀번호 변경 · 5번 틀리면 잠금 | ✅ |
| 3 | 호실 · 입실자 (입실예정 → 입실 확인 → 퇴실예정 → 퇴실 처리, 입실 취소, 방 이동) | ✅ |
| 4 | 월세 장부 (말일 보정, 부분·분할·선입금, 입금 취소 기록, 월세 변경, 보증금 정산) | ✅ |
| 5 | 자동 문자 (D-10·D-1·D+1·D+3, 테스트 모드, 중복 방지·재시도·긴급 정지) | ✅ |
| 6 | 솔라피 연결 (HMAC 서명, 시험 발송, 잔액, 응답 불확실 → 재발송 안 함) | ✅ |
| 7 | 공지·개별 문자 (템플릿, 대상 선택, 인원·비용 확인 후 발송, 실패 대상 표시) | ✅ |
| 8 | 노션: 처음 한 번 가져오기(미리보기·문제 줄 차단) + 사이트 → 노션 동기화 (마스터 제외, 퇴실 기록 DB) | ✅ |
| 9 | CSV 내려받기 · 전체 백업/복구 · 보관 기간 자동 정리 (3년 익명화 · 5년 장부 · 2년 이력) | ✅ |
| 10 | 배포 → 테스트 모드 1~2주 → 실제 발송 | 진행 |

## 규칙
- 계약 단위: **월 단위**(매달 같은 날) 또는 **2주 단위**(14일마다). 금액이 22만원 이하이면 등록·가져오기 화면에서 2주로 먼저 골라 둠 (바꿀 수 있음). 자동 문자 규칙은 둘 다 같음 (D-10·퇴실 7일 전 통보 문구 포함)
- 계약 단위 변경: 적용 시작일이 새 주기의 첫 납부일, 지난 장부는 그대로
- 노션 가져오기: 줄마다 '최근 납부분 받음' 체크 (기본값: 그 납부일이 이번 달 1일 전이면 받음, 이번 달이면 노션 입금 체크대로)
- 납부일: **처음 입실일의 날짜** 기준 매달 (1/31 → 2/28 → 3/31, 윤년 2/29)
- 납부 예정분은 납부일 10일 전에 그때 월세로 만들어지고 금액이 고정됨
- 입금은 오래된 납부분부터 채우고, 남으면 선입금으로 다음 납부분에 자동 충당
- 입금 취소는 지우지 않고 사유와 함께 "취소" 기록
- 한 호실에 현재 입실자 1명 · 사무실/수리중 호실은 등록 불가 · 퇴실 기록은 수정 불가
- 퇴실예정일·퇴실일 이후 납부분은 "해당 없음"
- 퇴실 시 보증금 공제액을 미납 월세에 충당 가능 (장부에 '보증금 공제' 입금)

## 구조
| 위치 | 내용 |
|---|---|
| `src/dates.js` | 한국 날짜 · 납부일 계산 |
| `src/ledger-core.js` | 입금 배정 · 입금 상태 (순수 계산, `npm test`) |
| `src/ledger.js` | 납부 예정분 만들기 · 배정 저장 |
| `src/api.js` | API (권한 검사, 변경 이력) |
| `src/db.js` | 표 자동 생성 |
| `public/` | 관리 화면 (휴대폰 기준) |

## 시험
- `npm test` : 날짜·배정 28가지
- `test/e2e.py` : 1~4단계 시나리오 50가지 · `test/sim-60days.py` : 자동 문자 60일 시뮬레이션
- 개발 환경(`.dev.vars`에 `DEV=1`)에서는 설정 화면에 **시험용 날짜**가 보여 날짜를 바꿔 가며 확인할 수 있음 (배포 환경에서는 꺼짐)

## 자동 문자 (5단계)
| 종류 | 보내는 날 (놓치면 보완) | 조건 |
|---|---|---|
| D-10 납부 예정·퇴실 확인 | D-10 (~D-8) | 그 납부분 미입금 |
| D-1 납부 안내 | D-1 (~당일) | 미입금 · 계좌 문구 필요 |
| D+1 1차 미납 | D+1 (~D+2) | 미입금 · 계좌 문구 필요 |
| D+3 2차 미납 + 운영자 알림 | D+3 (~D+5) | 미입금 · 계좌 문구 필요 |
| 운영자 입실 확인 | 입실일 (~+2일) | 입실예정인데 입실 확인 안 함 |

- 대상: 상태 '입실' + 문자 제외 아님 (퇴실예정·입실예정·퇴실은 안 보냄)
- 매일 09:00 자동 실행 (같은 날 두 번 실행해도 1번만), 발송 시간대 밖이면 보내지 않음
- 테스트 모드(기본): 보내지 않고 대상·문구만 실행 기록에 남김
- 같은 입실자·같은 납부분·같은 종류·같은 받는 쪽은 한 번만 (보내기 전에 기록부터 만듦)
- 실패 → 다음 실행 때 1번 재시도 → 그래도 실패하면 "결과 확인 필요"
- 응답이 불확실하면 다시 보내지 않고 "결과 확인 필요" (관리자가 실제로 감 / 다시 보내기 / 안 보냄 선택)
- 긴급 정지 버튼, 계좌 문구가 비면 D-1·미납 문자 보류
- 시험: 개발 환경에서 `SMS_MOCK=1` (가짜 발송: 0000으로 끝나는 번호 = 실패, 9999 = 응답 없음)로 60일 시뮬레이션

## 설치 (처음 한 번)
1. 위 **Deploy to Cloudflare** → 로그인 → GitHub 연결 → Create and deploy (데이터베이스 자동 생성)
2. Cloudflare → Workers → 이 프로젝트 → **설정 → 변수 및 비밀**에 **비밀(Secret)**로 추가
   | 이름 | 값 |
   |---|---|
   | `SOLAPI_KEY` | 솔라피 API Key |
   | `SOLAPI_SECRET` | 솔라피 API Secret |
   | `NOTION_TOKEN` | 노션 통합 토큰 (아래) |
3. 노션 통합: notion.so/profile/integrations → 새 통합(내부) → 토큰 복사 → 노션에서 입실자 현황이 들어 있는 **상위 페이지** ··· → 연결 → 그 통합 추가
4. 사이트 주소 접속 → **처음 설정**(최고 관리자) → 설정에서
   - 문자: 발신번호, 시험 발송 받을 번호, 운영자 알림 번호, 입금계좌 문구 (테스트 모드는 켠 채로)
   - 노션: 입실자 현황 주소 → 미리보기 → 가져오기 → 퇴실 기록 DB 만들기 → 지금 동기화
5. 문자 탭 → **내 번호로 시험 발송** → 휴대폰에서 확인
6. 설정 → 관리자 초대 → 링크를 김인준님에게 카톡으로
7. **테스트 모드로 1~2주** → 이상 없으면 설정에서 테스트 모드 끄기

## 테스트 모드 기간 매일 확인 (1분)
- [ ] 홈: 마지막 실행이 오늘 09시대인가
- [ ] 문자 탭 → 실행 기록: 대상 인원이 예상과 맞는가
- [ ] 오늘 보낼 문자: 이미 입금한 사람·퇴실예정인 사람이 들어 있지 않은가
- [ ] 문구 보기: 이름·납부일·금액·계좌가 맞는가
- [ ] 입금 받은 사람은 [입금 확인]을 눌렀는가

## 장애 대응
| 증상 | 할 일 |
|---|---|
| 잘못된 문자가 나갈 것 같음 | 문자 탭 **⛔ 긴급 정지** |
| "결과 확인 필요" | 솔라피 발송 내역에서 확인 → [실제로 감 / 다시 보내기 / 안 보냄] |
| 노션 동기화 실패 | 설정 → 노션 → 지금 동기화 (토큰·연결 확인). 사이트 데이터는 영향 없음 |
| 데이터를 잘못 고침 | 변경 이력 확인 → 직접 수정, 또는 백업에서 복구 / Cloudflare D1 시점 복구(7일) |
| 솔라피 잔액 부족 | 홈 "오늘 할 일"에 표시 → 충전 |

## 다른 고시원에 설치할 때
Deploy 버튼으로 새로 설치하면 데이터베이스가 따로 만들어져 섞이지 않습니다. 상호·발신번호·계좌·문구·노션 주소는 모두 관리 화면 설정에서 바꿉니다.
